```text
Provider type:   Groundmail
API Key:         gm_...
Webhook Secret:  whsec_...
Webhook URL:     https://senlo.io/api/webhooks/groundmail
```

## 1. Verify your domain in Groundmail

Senlo sends from the From email you set on each trigger or campaign. [Groundmail](https://groundmail.dev/) only accepts it from a domain verified in your Groundmail account (**Domains** in the dashboard, see [Domains](https://docs.groundmail.dev/domains)). Until then, sends fail at Groundmail and show `FAILED` in the delivery log with Groundmail's error.

## 2. Create an API key

In Groundmail, open **API Keys** and create a key that can send email. Copy it (`gm_...`); it is shown once.

A key that can only send works. Senlo then shows it as limited when it checks the key, because it cannot read your domains with it; sending is not affected.

## 3. Add the provider in Senlo

1. Open **Providers** → **Add Provider**.
2. **Provider Type**: Groundmail. **Display Name**: anything, e.g. `Groundmail acme.com`.
3. **API Key**: the `gm_...` key.
4. Leave **Webhook Secret** empty for now and click **Create Provider**.
5. In your workspace's **Settings**, select this provider.

Send a test from the [Quickstart](../getting-started/quickstart.mdx) to check it works.

## 4. Connect the webhook

1. In Groundmail, open **Webhooks** and add an endpoint: `https://senlo.io/api/webhooks/groundmail` (self-hosted: your `APP_URL` + `/api/webhooks/groundmail`).
2. Select `email.delivered`, `email.bounced`, `email.complained` and `email.failed`. Other events are ignored; opens and clicks are counted by Senlo itself.
3. Copy the endpoint's **secret** (`whsec_...`). Groundmail shows it once.
4. In Senlo, edit the provider and paste it into **Webhook Secret**.

From now on bounces and complaints suppress the address, and the delivery log shows `DELIVERED`. A `block` bounce (the receiving server refused the sender, not the address) does not suppress the address. Details: [Provider webhooks](../api/webhooks.mdx) and Groundmail's [webhook docs](https://docs.groundmail.dev/webhooks).

## Transactional and product email

Groundmail sends transactional and product email from separate IPs. Senlo sends automation emails as product email, and sends through the API ([`POST /api/triggered`](../api/triggered.mdx)) and test sends as transactional. Automation emails keep Senlo's own unsubscribe link and `List-Unsubscribe` header, so unsubscribes are recorded in Senlo as with any provider.

## Testing

Groundmail's simulator addresses let you try delivery outcomes without a real inbox: `delivered@simulator.groundmail.dev`, `bounce@simulator.groundmail.dev` and `complaint@simulator.groundmail.dev`, with real webhooks. They work on any Groundmail plan. Send to one of them with [`POST /api/triggered`](../api/triggered.mdx) and watch the delivery log. See [Testing](https://docs.groundmail.dev/testing#simulator-addresses).
