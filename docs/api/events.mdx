---
title: Send an event
description: POST /api/events records what a contact did and starts the automations listening for it.
---

```bash tab="curl"
curl -X POST https://senlo.io/api/events \
  -H "Authorization: Bearer $SENLO_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: invoice-in_1049-failed" \
  -d '{
    "event": "invoice_failed",
    "email": "ada@example.com",
    "metadata": { "plan": "pro" },
    "payload": { "invoiceId": "in_1049", "amount": 42, "currency": "EUR" }
  }'
```

```ts tab="Node"
await fetch("https://senlo.io/api/events", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.SENLO_API_KEY}`,
    "Content-Type": "application/json",
    "Idempotency-Key": "invoice-in_1049-failed",
  },
  body: JSON.stringify({
    event: "invoice_failed",
    email: "ada@example.com",
    metadata: { plan: "pro" },
    payload: { invoiceId: "in_1049", amount: 42, currency: "EUR" },
  }),
});
```

## Body

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `event` | string | yes | A system event (below) or any name of your own: lowercase letters, digits and `_ . : -`, starting with a letter or digit, 64 characters at most. `trial_started`, `invoice.paid`, `billing:failed`. |
| `email` | string | yes | Identifies the contact in this workspace. |
| `name` | string | no | The contact's name. |
| `locale` | string | no | The contact's locale; automations send the template for it. |
| `metadata` | object | no | **Contact attributes.** Merged into the contact's `meta`; not part of the event. |
| `payload` | object | no | **The event's own data**, at most 32 KB of JSON. Emails of the automation it starts read it as `{{event.*}}`. Not stored on the contact. |
| `idempotencyKey` | string | no | Same as the `Idempotency-Key` header (the header wins). Up to 255 characters. |

`metadata` describes who the contact is (plan, company, signup source) and stays on the contact. `payload` describes what just happened (the invoice, the order, the trial end date) and travels with the event.

## Events

Three names are system events with a side effect on the contact. Any other name is a custom event.

| Event | Contact must exist | Effect on the contact |
| --- | --- | --- |
| `contact_added` | no | Creates it. For an existing address: updates `name`, replaces `meta` with `metadata` if sent. |
| `contact_updated` | yes | Updates `name` and `locale`, merges `metadata` into `meta`. |
| `tag_added` | yes | Adds `payload.tags` (required, a non-empty array of strings) to its tags, without duplicates. |
| any other name | no | Creates it if new (which also fires `contact_added`); otherwise updates `name` and `locale` and merges `metadata`. |

Then the event is stored in the contact's event history, and every **active** [automation](../concepts/triggers-and-automations.mdx) whose trigger listens for that exact name starts a run for the contact, unless one is already running for them. An automation on `tag_added` can be limited to one tag; it then starts only when `payload.tags` contains it.

Events are kept as long as the workspace keeps its delivery log (see data retention in the workspace settings).

## Response

```json
{
  "success": true,
  "data": {
    "id": 31,
    "projectId": 4,
    "email": "ada@example.com",
    "name": "Ada",
    "locale": "en",
    "meta": { "plan": "pro" },
    "unsubscribed": false,
    "unsubscribedAt": null,
    "createdAt": "2026-11-03T10:15:00.000Z"
  }
}
```

`data` is the contact after the event. `projectId` is the workspace id.

## Idempotency

Send an `Idempotency-Key` header to make retries safe. The first request with a key is processed; a later one with the same key in the same workspace changes nothing, starts nothing, and answers `200` with the contact. Use a key that names the event in your system, such as `invoice-in_1049-failed`.

Without a key, the same event sent twice is applied twice and can start an automation again once the first run has finished.

## Errors

| Status | When |
| --- | --- |
| `400` | `email` missing or invalid, a malformed `event` name, `payload` over 32 KB, `tag_added` without `payload.tags`, a key over 255 characters. |
| `401` | No key, or a wrong one. |
| `402` | Cloud only: an automation run was refused by the plan's limits. The contact change and the event are already saved. |
| `404` | `contact_updated` or `tag_added` for an address that is not a contact. Send `contact_added` first. |
| `429` | Rate limited. |

See [Errors](./errors.mdx).
