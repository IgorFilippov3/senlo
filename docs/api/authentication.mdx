```bash
curl -X POST https://senlo.io/api/events \
  -H "Authorization: Bearer snl_abcdefghijklmnopqrstuvwxyz234567" \
  -H "Content-Type: application/json" \
  -d '{ "event": "contact_added", "email": "ada@example.com" }'
```

Every API endpoint needs an API key, sent as a bearer token in the `Authorization` header.

## API keys

- Create keys in the workspace under **API Keys** → **Create Key**.
- A key looks like `snl_` followed by 32 random characters.
- The full key is shown **once**, right after you create it. Senlo stores only a SHA-256 hash of it, plus its first 12 characters (`snl_abcdefgh`) so you can tell keys apart in the list.
- A key belongs to the workspace it was created in. Requests made with it act on that workspace only, which is why no workspace id appears in any request.

Keep keys on your server. Anyone with a `send` key can send email from your workspace.

## Permissions

A key holds one or both permissions, chosen when it is created:

| Permission | Allows | For |
| --- | --- | --- |
| `send` | `POST /api/triggered`, `POST /api/events`, `POST /api/automations/cancel` | Your app's backend |
| `manage` | API v1 (`/api/v1/*`): templates, triggers, automations, test sends to your organization's own addresses; and `/api/workflows` | Coding agents, the MCP server, scripts that set up a workspace |

A new key gets `send` unless you tick **Manage**. Keep them apart: the key in your production code then cannot rewrite templates, and the key you give an agent cannot send live email. A request with a key that lacks the permission answers `403` (`PERMISSION_REQUIRED`); `details.permission` names the one it needs.

Permissions cannot be changed after the key is created. To change them, create a new key and delete the old one, as when rotating.

<Callout type="warning" title="Keys created before permissions">
  Every key that existed before permissions were added has `send` only. It keeps sending; `/api/workflows` now refuses it with `403`. Create a key with **Manage** for importing and publishing automations.
</Callout>

## The header

```http
Authorization: Bearer snl_your_api_key
```

The scheme is case-insensitive (`bearer` works). A missing or malformed header answers `401` with `Missing or invalid Authorization header`; a key that does not exist answers `401` with `Invalid API key`.

```ts title="Node"
const senlo = (path: string, body: unknown) =>
  fetch(`https://senlo.io${path}`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.SENLO_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(body),
  });
```

## Rotating a key

There is no rotate button; rotate with two keys:

1. Create a new key.
2. Deploy your app with the new key.
3. Delete the old key. Requests with it fail with `401` from then on.

Delete a key the same way when it leaks.

<Callout type="info" title="Self-hosted only">
  Instances installed before keys were hashed may still hold keys in the clear. They keep working; `pnpm db:hash-api-keys` replaces each with its hash.
</Callout>
